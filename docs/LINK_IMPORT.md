# Link import 0.35

A short excerpt may fail before any media is downloaded: YouTube can challenge the cloud downloader. The desktop engine error recommends selecting a local browser, which does not apply to an isolated Vercel worker. Montara now maps that condition to external_verification_required / 422, retryable false, with file-upload and source-link actions. Local desktop advice is unchanged.

The media dialog shows real busy state while a request is active, stops it on error and offers file import. It clears the old selected asset at the beginning of a new link import so a previous clip cannot be mistaken for a successful download. Existing library items and project effects remain.

There is no CAPTCHA embedded in Montara, no remote browser or cookie transfer. A user-side YouTube check is not guaranteed to authorise the server downloader. Official YouTube iframe players are for playback, not importing editable footage. Upload an authorised original file for a reliable editing route. Short duration does not remove source metadata/access-check latency.

Validation: cloud error classification, desktop behaviour, unrelated errors, successful uploads and UI recovery. This is recovery from an external block, not a claim that blocked YouTube downloads now work.
