# Playhead and session recovery · 0.33

The 410 was a stopped Vercel Sandbox, not a refusal by the cut adapter. The named user Sandbox was observed stopped and resumed with its saved project. This is a temporary test environment, currently configured for sessions of up to 45 minutes. No paid server or GPU was purchased.

Scissors now performs a split at the current white playhead rather than enabling a second click tool. Ctrl/Command-click and right-click Split here still cut at the clicked point. A normal click selects the shot and seeks to the exact pixel clicked, not the shot's start. A split preserves the programme position; deletion maps the position through the removed interval.

The white playhead is a draggable, keyboard-accessible slider in video-cut, narration and effect tracks. Dragging the ruler or blank track seeks as well. All rows use the same clock. Effect bars retain their own move/trim gestures; orange handles retain boundary roll edits. Left/right arrows move a focused playhead by a frame, Shift by a second, Home/End by the part's endpoints. Cut boundary lines/grips are orange at rest, as requested.

HTTP 410 (or a lost preview session cookie) presents a Resume Montara link to the fixed public root. It does not automatically retry a destructive edit; the user checks the last edit after reopening. The saved project remains on the existing persistent storage.
