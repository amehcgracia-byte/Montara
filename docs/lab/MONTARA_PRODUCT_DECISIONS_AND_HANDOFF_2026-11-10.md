# MONTARA — Criterios de producto y traspaso de continuidad (10-11-2026)

## Decisión rectora (expresada por Fernando)
El **editor de Chema es el producto real**. Las pantallas I27/I28 que hicimos fueron smoke tests humanos de Google, autorizaciones, broker, Engine y persistencia; **NO** son diseños definitivos y NO deben desplazar ni duplicar el editor original. No continuar extendiendo el estudio provisional como una segunda interfaz de edición.

Conservar la portada de Cloudflare (mejorable más adelante), acceso Google operativo y eventualmente email/password tras desarrollo y validación segura. Después de login, el usuario debe ir **directamente al flujo original de selección de modo Stage / Push / Show de Chema**, sin pasar obligatoriamente por dashboard de proyectos ni activar Engine con un botón. Dentro de cada mundo, un control contextual «Mis proyectos» debe abrir un selector/modal/panel discreto para recuperar o crear proyecto (y asignar nombre) **sin navegar a página nueva**. Consultar a Fernando antes de alterar este recorrido o adoptar decisiones de UI/ingest: tiene conocimiento de preferencias de Chema e ideas para coordinarlas.

El Engine es backend de ingest/sincronización/análisis/edición/render, **no únicamente render final**. Arranque privado *bajo demanda* cuando el flujo requiere procesar; no al login ni necesariamente al seleccionar mundo. Respetar en lo posible el trabajo concurrente/preparación anticipada ya implementado por Chema (ver código y coordinar momento exacto de arranque antes de cambios). El control del Engine debe quedar invisible para el usuario. El frontend original consume hoy rutas `/api/v1/wizard`, `/api/v1/edit` y muchas otras rutas de Engine de un proceso global: **NO** poner un proxy global delante de esas rutas porque rompería el aislamiento por usuario.

El usuario puede arrastrar vídeos o seleccionar una carpeta como en el editor de Chema; ello **no implica subir originales enteros a GCP**. Companion local, con permisos/consentimiento informados, prepara proxies y conserva originales para las etapas que los requieran. Almacenar las identidades/fingerprints y selección autorizada para recuperar un proyecto sin exposición de rutas privadas. Preferir experiencia sin instalaciones, actualizaciones y preguntas innecesarias.

Fernando está en Windows 10 y tiene **prototipos/instaladores previos**, sin inventario de qué versión sigue instalada; **no limpiar ni reinstalar aún**. Existe prototipo Windows funcional previamente probado en rama Fernando. Debe evaluarse compartir lógica portable y crear bootstrap/updater Windows verificado, sin intentar instalar el paquete Mac en Windows.

Experiencia deseada: Companion instalado detecta nueva versión y ofrece «Actualizar»; componente local de confianza descarga un paquete **firmado/verificado** de origen estable, comprueba versión, termina/cancela actualización si hay renders, sustitución transaccional + rollback, sin pedir al usuario reinstalaciones manuales. Un sitio web no puede iniciar silenciosamente ejecutables arbitrarios en Windows sin un componente previamente instalado y autorización. No prometer actualización de un prototipo que aún no incluye el agente updater. Política de permisos, términos/privacidad, acceso a carpeta y tratamiento de archivos como parte del diseño futuro (sin afirmar consentimiento obtenido).

## Companion — Bandeja del sistema y actualizaciones (decisión de producto)
- En Windows, Companion debe seguir visible como icono pequeño en la bandeja junto al reloj (como en el prototipo validado); en Mac, equivalente mediante icono en barra superior. Menú sencillo de estado conectado, versión, trabajo activo, actualizaciones, preferencias y salir. No se requiere ventana permanente.
- Detección ligera de nuevas versiones; aviso discreto y botón **«Actualizar Companion»** desde el componente local. Si está inactivo, ejecutar actualización inmediatamente con intervención mínima. Si hay tareas activas (proxy, transferencia, render), posponer sin interrumpirlas, y actualizar cuando terminen de forma segura. El estado inactivo es el camino normal y rápido, no un proceso de espera artificial.
- Un actualizador local previamente autorizado debe verificar origen HTTPS, integridad/autenticidad del manifiesto/paquete y compatibilidad, sustituir de manera atómica, reiniciar servicio y permitir rollback. La web no ejecuta binarios locales directamente. En Windows contemplar firma de código y mecanismos OS apropiados; aprovechar las comprobaciones del instalador de Chema para Mac donde correspondan.
- Mantener una base de Companion compartida, con elementos específicos Windows/macOS. Primero inventariar las instalaciones Windows anteriores: **no borrar ni reinstalar** hasta comprobar versión, contrato y estado. Estas funciones son un objetivo, no una implementación declarada terminada.
